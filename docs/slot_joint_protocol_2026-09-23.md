# 单时隙联合编排实验协议（2026-09-23）

本协议取代旧的 Stage A/B/C 与 `formal_v*` 训练解释。那些结果的轨迹、动作单元和奖励口径不同，只保留为历史记录。当前可运行入口是 `scripts/run_slot_joint.py`；实现集中于 `workload/slot_trajectory.py` 与 `envs/slot_joint_env.py`。

## 依据与决策单元

参考 `微服务参考论文/博士答辩第四章.pdf` 的算法 4.3、§4.3.2 事件触发和式 (4-26)–(4-29)：一个训练回合覆盖固定的时隙序列；一个时隙内执行多个顺序决策；完成部署和路由后才给外部奖励；当前训练轮次与上一轮次相同时隙的指标相比较。这里保留本论文的物理模型与动作定义：LLM 候选部署 `y` 和无状态服务副本 `z` 由离散 PPO 动作构造，模型比例 `x_{a,g,:}` 由另一 PPO 分支按 `(应用 a, 接入节点 g)` 逐组采样，实例分配 `φ` 和无状态服务路由 `p` 仍由解析 Softmin 求出。同一 Agent 请求的各 LLM 节点使用同一模型。

只有物理时隙 `t`。部署步 `τ_D` 和模型路由步 `τ_X` 只是时隙内的决策索引，不触发负载抽样、成本计时或指标计算。每个时隙的顺序是：读取该时隙外生状态 → 遍历 LLM 候选二元动作与无状态服务池副本数动作 → 遍历全部 `(a,g)` 模型比例动作 → 计算解析物理路由 → 仿真一次 → 算指标、差分奖励并推进 `t`。部署每时隙从空的构造状态开始，实际实例增减费用仍与上一物理时隙的最终部署比较。

**部署动作（`slot_joint_v3`）**：固定顺序访问每个 LLM 候选一次，选 `0/1` 表示不部署/部署；随后固定顺序访问每个 `(无状态服务 h, 服务器 n)` 池一次，直接选整数副本数 `0,…,R_max`。共享部署策略头宽度为 `max(2,R_max+1)`；LLM 步只开放前两项，服务池步屏蔽超过 CPU、内存或副本上限的数值。当前已选择的部分部署、剩余资源和上一物理时隙最终部署进入观测。主场景每槽从 321 个部署子步降至 105 个，加 20 个模型路由子步共 125 步；这只是动作数量，不代表已证明样本效率改善。`slot_joint_v2` 检查点因动作头维度不同不能续训，入口会显式拒绝。

## 外生轨迹

`SlotTrajectory.sample` 在训练前用一个种子生成全部时隙。轨迹存入 `train_trajectory.json`，SHA-256 写入 manifest 和每次完成时隙的信息。每个 episode 从槽 0 回放同一轨迹，不随 episode 种子更改外生变量；PPO 动作本身仍可随机。留出评估使用另一个固定种子，存入 `evaluation_trajectory.json`。

每个时隙单独抽样如下量，默认范围只是可运行的暂定参数，正式数值须后续数据集标定：

| 量 | 当前抽样方式 | 时隙内 | 判断 |
|---|---|---|---|
| `(a,g)` 到达率 | 基准率 × U(0.6, 1.4)，逐组独立 | 固定均值 | 必须变化，形成总量与应用混合变化 |
| 应用 pattern flow 概率 | 以基准概率为均值的 Dirichlet，浓度 40 | 固定概率 | 必须变化，图结构与节点集合固定 |
| 各 LLM 节点、模型的输入/输出 token 均值 | 各自基准值 × U(0.8, 1.2)，截到模型最大上下文 | 固定均值 | 必须变化，表示该时隙的请求长度分布代表值 |
| 链路可用带宽 | 链路基准 × U(0.7, 1.0) | 固定 | 必须变化，传播时延与拓扑固定 |
| 服务器可用 CPU、内存 | 各自物理上限 × U(0.8, 1.0) | 固定 | 必须变化，代表背景负载占用 |
| 可用 GPU 个数 | 默认固定，支持配置 GPU 少一张的概率 | 固定 | 物理库存固定；无故障标定前不人为制造 GPU 故障 |
| SLO 阈值 | 固定 | 固定 | 属于应用服务契约；后续若研究契约变更另设实验轴 |
| 模型质量、服务速率、GPU 性能、资源价格 | 固定 | 固定 | 属于静态 profile，后续由数据标定 |

抽样后检查每个时隙是否存在可行的确定性贪心参考部署；不可行抽样会重试，超过 100 次报错。此处没有宣称这些范围来自数据集，也没有从旧实验推断有效性。

## 奖励与 PPO

目标评估器输出四个归一化指标 `cost_normalized`、`latency_normalized`、`goodput_normalized`、`quality_normalized`。暂以四项各 0.25 的建模权重构成效用，并增加 SLO 达成率 0.9 的显式约束；这些权重和门槛仍需标定。令 `v_k(t)` 为训练轮次 `k` 的时隙 `t` 指标向量，`u_k(t)` 为对应加权效用。时隙性能差分是 `u_k(t) − u_{k−1}(t)`，信息中同时记录四个分项差值、原始指标差值与约束差值。第一轮的 `v_{−1}(t)` 是固定贪心策略在**相同训练轨迹**上的结果，先于训练计算并落盘。PPO 的实际外部奖励还须减去当前绝对约束违约量乘以对应拉格朗日乘子；该绝对量也用于更新乘子。

部署子步与尚未结束时隙的模型子步不产生外部奖励。时隙最后一步的奖励通过折扣为 1 的子步和 GAE 回传给同一时隙的两个 PPO 分支；跨时隙折扣仍取 PPO 配置的 `γ`。训练入口强制每次更新收集一个完整 episode，避免在时隙中间更新策略。RND/ICM 可显式打开，默认不加入探索奖励，以便先核对差分奖励本身。

**2026-09-23 约束修正（`slot_joint_v2`）**：四项性能效用仍作同槽、上一 episode 差分，但拉格朗日惩罚使用本轮本槽的**绝对违约向量**，而非违约差分；乘子更新也使用同一绝对向量。否则连续两轮违约量相同会导致 actor 惩罚为零、乘子却继续上升。新协议的约束向量依次为 LLM 最大利用率超额/故障、无状态服务最大利用率超额/故障、网络链路最大利用率超额/故障、总体 SLO 达标率缺口。利用率目标暂均为 0.9；故障标签与超额取最大值，避免重复叠加。旧目标档案不自动增加网络维度，以保留历史代码口径。当前还没有逐应用 SLO 达标率字段，不能宣称已实施逐应用约束。

**2026-09-24 时隙汇总修正（`slot_joint_v4`）**：逐组模型选择时，一个物理时隙产生多个中间子步，但仅最后一个子步有仿真指标。PPO 终端奖励仍按前述口径；训练日志中的时隙效用、违约均值，以及拉格朗日乘子更新，只从 `period_complete=True` 的记录按物理时隙聚合。v3 曾把中间子步的零约束一起平均，导致主场景约 20 倍的稀释；v3 检查点与 v4 训练口径不得混用。修正不改变时隙轨迹、动作顺序或部署框架。

**阶段训练**：同一个环境、同一条固定外生轨迹、同一套时隙评价，依次执行模型选择预训、冻结模型选择训练部署、联合更新。模型选择预训时，各时隙分别由贪心可行部署加可行随机扩充形成不同上线模型/副本组合；**同一时隙的参考部署在各 episode 固定**，避免把部署变化混入同槽奖励差分。部署仍按原有从空表顺序构造流程重放。部署训练时模型选择策略冻结；联合阶段两分支一起更新。`--route-updates`、`--deploy-updates` 设置前两阶段更新数，余下为联合更新数；零更新允许单阶段调试。阶段切换时重建只包含可训练参数的优化器，不改变物理时间轴。部署和模型选择分别使用其决策阶段的观测编码器与价值头；部署局部观测显式含上一时隙最终部署，模型选择局部观测含当前 `(应用,接入节点)` 的负载、SLO、pattern 概率摘要、token 均值、质量与已上线模型数。两分支仍以相同的时隙终端效用/约束为目标。

用户已明确本轮不改时隙抽样范围、每轮重放和每时隙从空部署表构造的约定。配置中的 `slot_seconds=1.0` 仅是现有占位数值，正式时隙时长待确定，本轮不把它解释为真实 1 秒部署。

## 运行与审计

```powershell
conda activate agent-orch
$env:PYTHONPATH='src'
python scripts/run_slot_joint.py --scenario configs/toy.yaml --output results/slot_joint_toy --slots 8 --updates 10
python scripts/run_slot_joint.py --scenario configs/benchmarks/main_abilene.yaml --output results/slot_joint_main_v4 --slots 60 --updates 100 --trajectory-seed 101 --mapping-samples 128
```

输出目录包含 `manifest.json`、训练/留出轨迹、`fixed_baseline.json`、`checkpoint.pt`、`policy.pt`、`history.json`、`evaluation.json`、`baselines.json`。留出轨迹上同时评估 greedy、equal、least-load、random，采用同一目标评估器与时隙条件。从中断处继续须使用完全相同的参数及 `--resume`，包括原先的总 `--updates` 和阶段划分；当前入口不能把已完成的 120 次更新直接改成 160 次无损续训。脚本拒绝覆盖已有运行，也拒绝与 checkpoint 不一致的轨迹、场景或训练参数。

2026-09-24 已完成主场景**模型选择阶段**两个 PPO 种子、各 120 次更新及五条留出轨迹的诊断；结果见 `docs/slot_joint_route_long_2026-09-24.md`。部署 PPO、联合训练和数据集标定尚未完成，因此没有正式多种子联合编排结论。论文结果仍需在标定后，以同一留出轨迹对照基线，报告效用、约束、SLO、收敛和计算开销。每种方法共享同一组外生轨迹，PPO 随机种子另行重复。

## 论断与证据缺口

| 待验证论断 | 必需证据 | 当前证据 | 下一项实验 | 风险 |
|---|---|---|---|---|
| 在动态应用与资源下提升联合编排效用 | 同轨迹基线对比，跨多种外生轨迹与 PPO 种子 | 协议与 toy 冒烟 | 标定后的主场景多种子对照 | 高 |
| 分层部署和模型选择都有效 | 去除任一 PPO 分支的消融，保留相同求解预算 | 尚无 | 联合、仅部署、仅模型比例三组 | 高 |
| 满足 SLO 与资源约束 | 达标率、各类违反量、最坏时隙 | 仅 toy 结构验证 | 主场景及压力轨迹约束统计 | 高 |
| 奖励差分改善训练 | 与相同轨迹的绝对效用奖励对比 | 同动作复播差分为零的单测 | 收敛与方差消融 | 中 |
