# 单时隙联合编排实验协议

> 当前版本：**slot_joint_v7（2026-10-14）**。保留容量比例路由、固定工作负载和训练轨迹重放；通信采用固定计量窗口，成本为率，时延仅统计完成请求并按应用等权平均。旧v3–v6协议不续训、不按新口径重新评分。历史数值保留为历史。详细来源与变化见`docs/metric_conventions_2026-10-14.md`。

## 1. 时间轴与三阶段训练

2026-10-14更新：主仿真改为A10/L20/H20，每GPU使用对应在线默认；同配置同机可有多个二元实例候选，数量由卡数推导，副本ID重标号不增加加载费。传播0.2–2ms。当前负载/跨槽扰动不随资源规模调整，SLO仍待后续确定，不改训练框架或容量比例路由。

参数表为唯一设置依据，主入口读取`configs/experiment_settings.yaml`，不从Abilene/GEANT继承硬件或工作负载。`build_registered_scenarios.py`从一池构造多种网络/嵌套子集，GPU候选由固定版本模型和显式资源假设推导。候选仅用于预实验，`--formal`要求参数已冻结。登记范围仍是10–50台，未自动采用扩展建议。

每回合从时隙0重放固定外生轨迹。每槽先顺序部署LLM候选的二元启用状态和工具—服务器池的整数副本数，再逐(应用,接入节点)选择模型比例，最后解析路由、完整工作流评价和共同反馈。子动作不推进物理时间。部署从空表构造，但切换费用与上一物理槽最终部署比较。

保持同一环境、两类观测/actor/critic和三阶段安排：固定多样部署下训练模型选择；冻结模型选择、使用其Dirichlet均值训练部署；最后共同更新。模型选择阶段直接安装固定部署，不回放部署actor子动作。各场景独立随机初始化，主方法无教师、蒸馏、ICM/RND。贪心只用于首轮参照和部署上下文构造。

--route-updates、--deploy-updates设置前两阶段预算，剩余为联合更新。每次更新收集完整episode。实际阶段预算、网络/小批量、总回合及轨迹时隙数仍须按参数登记表冻结，不以默认值冒充正式设置。

## 2. 外生轨迹

SlotTrajectory.sample在训练前生成整条轨迹，写入train_trajectory.json。摘要进入manifest、检查点和时隙信息；每次episode重放相同数值。

| 量 | 当前方式 | 跨时隙 |
|---|---|---|
| 应用—入口到达率 | 基准率乘U(0.6,1.4) | 可变化；零率仍为零 |
| pattern概率 | 精确复制基础应用配置 | 不变 |
| 输入/输出token | 精确复制基础节点参数，不再比例缩短 | 不变 |
| 带宽 | 基准乘U(0.7,1.0) | 可变化 |
| CPU/内存可用量 | 基准乘U(0.8,1.0) | 可变化 |
| GPU库存 | 主实验无故障 | 不变 |
| SLO、模型质量、服务profile和价格 | 场景给定 | 不变 |

扰动范围是现有合成暂定值。概率/token随机扰动字段已移除；读取的轨迹若跨槽改变概率或长度，会明确拒绝。槽资源采样仍检查贪心参考部署可构造性，最多100次尝试；这是轨迹模块的资源筛选规则，不是SLO达标证明。大规模图与工具文本48–5,000 token的联合生成已实现，见`docs/agent_generator.md`；应用生成器不调用该部署筛选器。

## 3. 唯一物理路由

模型m的请求流(a,i)权重为访问概率乘sum_g(lambda_ag*x_agm)，保留其输入输出token对；为在线配置计算同组成参考容量。LLM比例为x_agm乘mu_ref_l在同模型、在线、入口可达、正容量集合内归一化。工具从上游执行服务器出发，按可达池的z_hv*mu_hv归一化。

历史利用率和时延评分不参与路由；实际负载下的排队、通信与SLO由最终性能模型评价。没有可用支持集时保持空分配并标记不可服务。参考容量缓存使用完整输入键，不取整合并；模型选择改变组成时重新求容量。

Softmin实现及专用诊断已删除，通用环境与旧内层求解器的物理分配也改用容量比例。未提交的旧探针原文件没有修改，其依赖不再受支持；历史数据不能被重标为容量路由结果。

## 4. 目标、约束与反馈

四项归一化指标为成本、时延、达标比例和质量，当前入口各权重0.25；请求级goodput仍单独报告为速率。效用为四项加权和，本轮同槽效用减上一回合同槽效用；首轮采用同轨迹固定贪心参照。

网络业务率为Mbps，固定计量窗口默认1秒，聚合传输近似为窗口业务量/链路速率加传播时延；窗口不是物理时隙长度。成本按每秒运行/通信费率加新增部署费用/固定摊销时长计算，摊销示例为60秒；两项常数是本研究可配置示例，不是前作文献数值。`slot_seconds`不再影响这些计算。`running_cost_per_slot`、部署库`cost_per_slot`等历史字段名按成本率解释，不能称为实际每槽账单。

只有完整、稳定、可达的物理映射计入完成。已完成但SLO不达标仍计入时延，未完成请求不计入均值，且goodput为零。记录`completed_rps`、`failed_rps`和逐应用完成率；无完成请求的应用不出现在`app_latency_s`，整个时隙无完成请求时`mean_latency_s=null`。系统时延为有效应用等权平均，轨迹汇总先在应用内部按完成量合并，再按应用等权平均。训练中缺失应用使用独立归一化评价值1，不将其称为实际时延，观测与奖励保持有限。

成本归一化改为固定可行参照成本率：有部署库时使用其稳态费率中位数，否则使用固定贪心可行部署；不使用全部候选的物理不可达上界，也不截断超参照成本。各回合及同场景各方法共用冻结尺度。时延默认仍为原clip映射；smooth可用但本轮没有擅自切换默认。

工具池的副本上限仅由CPU/内存推导。部署类别头宽度由整条轨迹的最大物理上限固定，逐步资源掩码处理共享占用；旧配置中每池上限4的字段读取时忽略，源码与当前配置不再使用它。

奖励再减当前绝对违约量乘拉格朗日乘子。四维约束依次为LLM、工具、网络及总体SLO；故障/不可服务标记与最大利用率超额取较大值，总体达标缺口取正部。目前利用率和总体达标目标为0.9占位值，后续冻结。没有逐应用约束保证。

中间子步奖励为零，时隙末共同反馈通过槽内折扣1与GAE回传；跨槽折扣取配置gamma。日志及乘子更新只统计完成物理时隙的记录，避免零奖励中间步稀释指标。保留当前分支冻结、奖励参照与优化器阶段切换行为。

## 5. 训练轨迹内评价与恢复

训练结束、快照诊断及模型选择基线均读取同一train_trajectory.json，核对摘要、长度和种子，不重新采样。没有evaluation_trajectory.json和额外评价种子。提高映射精度不改变业务轨迹。结果是训练场景内评价，不能称为未见轨迹泛化。

manifest记录evaluation_protocol=training_trajectory_replay及physical_routing=capacity_proportional，检查点附协议与轨迹来源。场景哈希、训练配置、轨迹或协议不同则拒绝恢复。只能以原定总更新数和阶段预算恢复中断运行；不直接延长已完成训练。正式检查点选择规则尚待冻结，不引入验证集。

```powershell
conda activate agent-orch
$env:PYTHONPATH='src'
python scripts/run_slot_joint.py --scenario configs/toy.yaml --output results/slot_joint_v7_toy --slots 2 --updates 2 --route-updates 1 --deploy-updates 0 --smoke
python scripts/evaluate_slot_joint_snapshot.py --run results/slot_joint_v7_toy --mapping-samples 128 --baselines
```

输出包括manifest、单条训练轨迹、固定基线、检查点、最终权重、训练history和评价/基线JSON。只完成短功能验证不代表正式模型选择、部署或联合性能已经验证。
