## 1. 本次确定了什么

每个应用只标定一次，使用 **Qwen3-8B＋单卡 L20** 的固定低负载参照。按该应用各执行子图的发生概率计算工作流时延的加权 q95，再乘预先声明的倍率。所有服务器规模、应用嵌套子集及工具重绑定场景继承相同阈值，不随训练结果、资源数量或策略表现重新调整。

| 指标 | main | tight |
|---|---:|---:|
| 工作流 TTFT | 参照 q95 × 1.5 | 参照 q95 × 1.2 |
| TBT | 参照 q95 × 1.25 | 参照 q95 × 1.0 |
| 完整响应时延 | 参照 q95 × 1.5 | 参照 q95 × 1.2 |

main 倍率与 8B/L20 参照由用户明确确认；tight 采用标定执行前声明的 main × 0.8，未按训练结果选取。时延敏感型应用使用 TTFT/TBT，截止期型使用完整响应时延，复合型同时使用三者和中间推理阶段截止期。没有改变应用原有 SLO 类型、质量参数或最低达标率目标。

这里的 q95 是**不同 pattern 的解析工作流时延，按其发生概率形成的分位数**。不是在真实服务器采集的大量请求的 P95，也没有估计随机排队等待的尾分布。各指标分别取 q95，不自动保证联合事件有 95% 概率；联合达标比例另行计算并报告。

## 2. 参照环境与计算

每个应用在独立参照网络中测算，不把 200 个应用同时塞入一张 L20。参照包含一个入口、一台单 L20 推理服务器、各实际使用工具类型的一台独立服务器及一个副本。工具沿用原单副本 CPU、内存、处理率和到达变异系数；同一工具类型在不同节点出现时共享该参照副本。网络按入口—LLM、工具—LLM 双向连接，每方向 100 Mbps、每跳传播 1 ms。

低负载探测率固定为每应用 `1e-6 request/s`，只写入临时参照对象。最大参照利用率必须不超过 0.01，且所有正概率 pattern 均须能够完成，否则停止标定，不删去困难 pattern。此次实际最大利用率为 **7.2253441e-6**。原训练应用到达率及其时隙波动没有修改。

参照 L20 配置完整保存在合同文件中：BF16、单卡 48 GiB、有效算力 119.5 TFLOP/s、有效显存带宽 648 GB/s、可用 KV token 容量 195905、批 token 预算 2048、最大序列数 256、关闭前缀缓存。批处理沿用当前解析模型；有效硬件参数仍为已登记的合成候选，不是此次测得的硬件性能。

逐 pattern 使用已有解析性能与关键路径模型计算工作流 TTFT、TBT、完整响应时延。参照只有一个模型实例及每种工具的一个位置，因此各 pattern 的物理映射唯一，没有把多个位置的平均时延拿来冒充请求尾分布。原占位 SLO 在临时参照中设为非约束，不参与时延生成或样本筛选。

复合型应用的中间 LLM 节点，使用“该节点作为中间阶段被执行”条件下的完成时间 q95。完成时间从请求进入工作流起累计，并非该节点自身处理时间。main 阶段截止期取 `min(应用完整截止期, 阶段参考 q95 × 1.5)`；tight 使用对应的 1.2 倍。合计生成 **263 个**阶段阈值。

## 3. 标定结果

固定应用池共有 **200 个应用配置、1171 个正概率 pattern**；SLO 类型为 lat 78、ddl 56、cmp 66。以下统计对适用该指标的应用等权计算，单位已注明：

| main 阈值 | 应用数 | 最小值 | 中位数 | P90 | 最大值 |
|---|---:|---:|---:|---:|---:|
| TTFT（秒） | 144 | 0.148 | 47.081 | 113.885 | 197.437 |
| TBT（毫秒） | 144 | 32.148 | 33.699 | 36.821 | 45.784 |
| 完整响应时延（秒） | 122 | 0.997 | 65.104 | 147.626 | 226.998 |

工作流 TTFT 包含前序推理、工具执行以及最终推理的首 token 等待，不能与单次 LLM 推理的 TTFT 混用。多轮应用出现几十秒甚至更大的阈值，是当前 token/结构和固定参照模型共同产生的结果；本次没有人为统一成 2 秒，也没有按这些结果缩短 token。

在各自的隔离低负载参照环境中，使用完整 SLO 判据重新计算联合达标比例：

| 阈值档 | 最低单应用达标比例 | 应用等权平均 |
|---|---:|---:|
| main | 95.700% | 99.776% |
| tight | 95.146% | 99.568% |

**上述比例不是实际训练网络的达标率。** 不同应用共享有限资源后，部署、模型选择、排队和未服务请求都会降低结果。

为检查这一差别，另在 N=20、A=50 的 main 场景以原始名义到达率运行一次 EqualSplit 固定策略和容量比例物理路由，映射采样上限 128：总到达率 0.656621 request/s、完成率 0.328310 request/s、失败率 0.328310 request/s，SLO 达标比例 **27.125%**、goodput 0.178105 request/s，仅完成请求的应用等权平均时延 50.602 秒。未服务约 50% 意味着不能把全部损失归因于阈值太紧，也不能据此宣布其他部署无可行解。本次未据此放宽 SLO、降低负载或修改模型。

- 输入场景、标定配置、固定模型/LLM 配置和实现源码摘要均保存在合同中。

合同分别保存原参照工具参数与完整工作负载摘要，以及不包含工具绑定编号的逻辑请求摘要。改变服务器数、入口分配、负载、工具绑定或处理容量不重标 SLO；改变图、pattern 概率、token 或通信需求则属于新的逻辑请求，必须显式重新标定，不能静默回退到旧占位值。

`configs/experiment_settings.yaml` 的 `slo_contracts` 指向冻结文件。多网络构建器、单网络生成器和工具重绑定接口自动应用合同；主训练前审计校验实际阈值及逻辑请求。场景 ID 包含合同摘要和 main/tight，运行来源记录合同文件 SHA256，防止错用旧缓存或续训。

原始 `pool.json` 不覆盖，仍保留生成时的占位 SLO，实际训练必须使用构建后场景中的冻结阈值。原型文件移至忽略目录 `results/slo_reference_prototype_20261014/` 留存；定稿增加逻辑请求签名与来源信息，200 个应用的数值阈值逐项保持相同，没有依据策略成绩挑选版本。

## 5. 执行与核验

在仓库目录激活 `agent-orch` 环境，设置 `PYTHONPATH=src` 后执行。首次标定命令如下；已有输出目录不会被覆盖，复现应换一个新目录：

```powershell
python scripts/calibrate_synthetic_slos.py `
  --scenario results/datacenter_gpu_replicas_20261014/servers_20_applications_200.yaml `
  --output data/catalogs/slo_reference_20261014

python scripts/build_registered_scenarios.py `
  --pool results/datacenter_gpu_replicas_20261014/pool.json `
  --servers 10,20,30,40,50 --subsets 20,50,100,200 `
  --output results/slo_calibrated_main_20261014

python scripts/build_registered_scenarios.py `
  --pool results/datacenter_gpu_replicas_20261014/pool.json `
  --servers 10,20,30,40,50 --subsets 20,50,100,200 `
  --slo-variant tight --output results/slo_calibrated_tight_20261014
```

两档各生成 20 个场景，均通过逐场景审计与 YAML 往返检查。额外逐一比较 40 个输出场景和对应旧场景，确认除 SLO/阶段截止期及相应 ID/元数据外，图、概率、token、质量、到达率、工具、服务器、链路、候选、仿真及奖励配置全部保持原值；同一应用跨 N/A 使用同一阈值，保存的池文件字节不变，来源摘要与当前配置一致。

工具重绑定额外生成 20/50/100/200 类型四个场景，输出 `results/slo_calibrated_tools_20261014/`，使用相同逻辑请求合同，不重抽图或 token。

## 6. 后续训练的边界

本次完成合成 SLO 标定，不代表所有正式参数已经冻结。GPU 有效效率、实际 KV/固定 chunk 校验、价格、规模点、质量与学习预算等仍由参数表和 `pending` 列出。正式训练入口继续拒绝未冻结配置。

后续预实验应同时看完成比例、逐应用达标比例及资源违约，区分“未服务”与“已完成但超时”；不得只看完成请求平均时延判断好坏。当前观测保留原缩放/截断规则，少数长 TTFT/截止期可能触及特征上界，学习诊断时应检查饱和比例；本次没有为适配阈值而改写观测或训练框架。

这些阈值是可复现的仿真合同。真实 K8s 实验仍需在目标服务器验证时延模型与测量口径，不能直接把本文件数字写成已经实测满足的用户 SLA。
