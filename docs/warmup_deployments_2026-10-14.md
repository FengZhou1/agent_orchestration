# 模型选择预训的固定多样部署

## 1. 部署序列如何进入训练

为每个物理槽提供一份固定部署D_t。模型选择阶段直接安装D_t，再逐正到达率的(应用,入口)选择模型；同一槽跨回合始终是同一部署和同一外生条件。不同槽改变部署，使预训能够观察不同模型可用集合、容量分配及工具位置。

部署序列只用于composition；deployment和joint仍从空表由部署actor构造完整方案，动作空间不受库限制。首轮仍使用原固定贪心完整方案参照，后续比较上一轮同槽；本轮没有更换奖励或教师预训练。相同上下文下的模型选择基线、最终评价及快照诊断均读取保存的同一部署序列。

## 2. 显式的合成生成规则

来源是本次受控覆盖设计，不声称出自Energy、博士论文或vLLM默认。只在现有参数范围内生成，不修改工作负载、SLO或资源参数。

| 维度 | 规则 | 边界 |
|---|---|---|
| 在线模型集合 | 对4模型目录循环2/3/4模型集合及各具体子集 | 小目录按可用模型数适配；不能装下目标子集时重试并最终报错，不偷改集合 |
| GPU占用目标 | 实际库存的35%、55%、75%、90% | 不是所有候选需求之和；目标为软限，必要模型覆盖优先，整数GPU使实际占用不同 |
| 模型容量分配 | 均衡、轻模型偏置、大模型偏置 | 偏置权重按模型参数量排序为1,1/2,1/4,…；不是质量排序，不断言大模型适合所有应用 |
| 配置与位置 | 候选配置轮换；分散、接入近、集中、工具近 | 使用合法候选和当前资源掩码；报告实际部署而非把标签当成功覆盖 |
| 工具副本 | 正业务率工具先至少一个；依该槽到达量及单副本速率补到目标容量 | 目标利用率0.45/0.70/0.90；有限资源未达到目标时记录风险，不能缺少必要工具 |
| 工具冗余 | 0/0.20/0.45概率为各必要服务额外增加一副本 | 提供冗余/位置差异；不为闲置工具充数；不是统一每池1/2/4副本 |
| 构造尝试 | 每槽最多48次 | 仅资源覆盖/重复布局重试，不比较PPO效用或SLO达标率 |
| 容量修复 | 三个探针均不过时，最多补到实际GPU库存95%的软限 | 补充均匀分配下容量不足的模型，不产生模型选择标签；风险无法消除也保留并标记 |

LLM容量使用当前槽请求组成：原节点输入/输出对、访问概率和各应用到达率共同加权。不能只按GPU峰值估计，也不能在到达率改变后复用基础槽的请求组成。工具副本数由实际请求量和服务器处理率推导；CPU、内存和GPU均逐步共享占用。

布局去重忽略同(模型,配置,服务器)的replica_index重标号，按实例数与实际工具副本位置计数。不能把候选编号交换称作不同部署。各槽资源不同仍逐槽验算。

## 3. “合理”如何核验

必须满足：所有二元/整数动作合法；物理GPU、GPU显存、CPU、内存可行；正业务工具都有副本；在线模型与工具、正请求入口之间的路由支持可达。上下文要求其所有正路由支持互相可达，适用于当前双向连通随机网络，不为一般不连通网络声称适用。

额外检查三组预先声明的全局模型比例：均匀、偏轻、偏大。每组均遵循当前容量比例物理路由，并计算LLM容量负载比、工具池及链路利用率。全局模型比例使各模型内部请求组成不随该比例改变，故可复用同槽完整组成的参考容量；不同槽仍须重新计算。

“通过容量筛查”不等于完整稳态存在、全部SLO达标或策略任意动作都可行。三组均失败也不证明没有其他可行模型比例。此处不运行最优模型选择搜索，不输出监督标签，不按SLO筛选，未消除风险写入文件。可选工作流诊断在部署保存后进行，不参与生成或修改方案。

上下文绑定整个Scenario（包括应用、token、质量、SLO、资源）及轨迹摘要。加载、checkpoint恢复和快照评价须匹配。训练运行会将同一序列保存到自己的输出目录，不依赖外部路径在运行期间保持可写。

覆盖采用错周期安排，避免2/3/4模型数量分别锁定某种容量偏置或工具档位。32槽分别检查每种模型数量是否覆盖三种偏置、四个GPU目标、四种放置和三种工具档。它不是全部具体模型子集与全部因素的完整笛卡尔积；具体子集的曝光次数另外报告。


## 6. 最终生成结果

20台服务器、50应用、77种实际工具，固定32槽；本网络实际有25张GPU，不把服务器数量误称为GPU数量。

| 检查项 | 结果 |
|---|---|
| 不同物理布局 | 32/32，无重复 |
| 在线模型数 | 2模型11槽，3模型11槽，4模型10槽 |
| 具体模型集合 | 全部11种二/三/四模型子集均覆盖 |
| 每槽LLM实例 | 5–22 |
| 每槽GPU占用 | 8–22张；四个软占用档实际为32%、52%、72%、88% |
| 每槽工具副本 | 77–120，覆盖全部77种正业务工具 |
| LLM/工具位置 | 分别覆盖4–16、4–20台服务器 |
| 配置多样性 | 13种实际配置；14槽含同配置同机多副本 |
| 硬资源、必要服务及路径 | 全部32槽通过 |
| 构造尝试/容量修复 | 全部一次构造成功，无需容量修复 |
| 固定混合容量筛查 | 95/96通过；32槽均至少一种比例通过 |

唯一不通过的是零基槽17的偏大模型探针，32B容量负载比约1.170；同一部署的其他探针可通过，因此保留这个需要正确模型选择的上下文，而非删掉困难情形。每一种在线模型数量都覆盖三种容量偏置、四种放置、四个GPU目标及三种工具配置档；并不声称11种具体子集都覆盖全部因素组合。

保存后，在零基槽2的同一四模型部署上，以128映射样本计算三种固定比例的完整工作流：

| 比例探针 | SLO达标率 | 应用等权完成请求时延/s | 质量 |
|---|---:|---:|---:|
| 均匀 | 0.6792 | 31.8625 | 0.6888 |
| 偏轻模型 | 0.8550 | 23.9398 | 0.6320 |
| 偏大模型 | 0.3204 | 47.7625 | 0.7535 |

三者失败量仅有1e-16量级浮点残差。这只是固定比例的诊断：显示同一部署下时延/SLO与质量的权衡，不代表最优模型比例、PPO成绩或所有槽的效果。未用这些分数更改或筛选部署。主场景只作保存后核验，没有全量重复重生成，verification中的该项为null；完整确定性重生成由toy测试覆盖。
