## 实现边界

`workflow.py::_physical_mapping_outcomes` 和标量关键路径计算保持为对照。
`workflow_mapping.py` 将相同的物理执行位置写入 `MappingBatch`，不是删除或合并位置：

- 候选及节点排序、笛卡尔积行顺序、逐项概率乘法不变。
- 超过映射上限后仍使用原固定样本数；哈希种子按原代码以 **big-endian** 解释。
- 按样本优先、排序节点次序生成均匀数，复制 `Generator.choice` 的两次归一化与 CDF 查找；单候选与缺失候选也消费对应随机数。
- 相同的拓扑递推及 float64 顺序加权，先判断每个位置方案的完成状态和 SLO，再累加概率。
- 保留全部逐应用、逐 flow 诊断；主进程仍按原应用—入口—模型—pattern 顺序逐项汇总，未改成应用小计归并。

每次全网解析评价后重新装配动态性能表。概率支持集只在本次应用评价内去重；跨评价唯一新增的数据缓存为固定均匀数，按完整应用/入口/模型/pattern/样本数/排序节点绑定，LRU 每进程上限 64MiB。
不缓存历史 rollout、全部物理映射或仅按部署命中的完整结果。

## 可选进程池

`WorkflowRuntime` 由一次训练运行持有，跨时隙 Simulator 复用，退出时关闭。
先完成全网负载和队列计算，再将单应用数值上下文提交到常驻 Windows spawn 进程。
只传该应用的参数、候选支持及全局性能数组，不传 PPO、Gym、rollout 或分析后端。
最多有 worker 数量个应用任务待交付；父进程按提交顺序取回，worker 出错直接报错并关闭池。
仅允许 1/2/4 进程，无嵌套进程、共享内存或自动增大并行度。

`workflow_sampling/numeric/aggregation/assembly/serialization/deserialization/process_wait`
为性能计时，不属于 `SlotMetrics`。并行数值计算时间是各 worker 时间之和，
`process_wait` 包含等待计算和传输，不能将两者相加当成端到端墙钟时间。
缓存占用由独立运行时诊断报告，不进入指标与奖励。

运行选项单独保存于 manifest/checkpoint 的 `workflow_runtime`，不改变协议 v7 或参数摘要。
旧 manifest 缺字段时解释为 reference/1。恢复时未显式传入的字段继承保存值，
显式变更写入 `workflow_runtime_switches`；科学参数和优化器恢复仍由原严格检查控制。
训练固定参照、训练、训练后评价及全部基线共用同一运行时。

`benchmark_slot_runtime.py --run` 校验场景、轨迹、部署库和检查点来源，读取保存的网络配置、目标、策略权重与奖励历史，不再使用旧的临时预训部署。
32 槽无更新 probe 对已完成所有槽的检查点使用其上一轮参照，不重算不会被使用的首轮贪心参照；这仅避免 probe 初始化冗余，不改变正式训练初始化。
标量对照使用 `--workflow-engine reference --scalar-workflow`。
